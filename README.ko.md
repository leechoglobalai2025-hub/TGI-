# TGI-RCS — 언어 모델의 가중치 안에서 "루프 유령" 스캔하기

> 🇰🇷 한국어 | 🇨🇳 [中文](README.zh.md) | 🇺🇸 [English](README.md)

**이조글로벌인공지능연구소 (LEECHO Global AI Research Lab) & Claude Fable 5.2 · Anthropic** · 2026-11-15 ~ 2026-11-17

이틀간의 실험 기록입니다. TGI(Training Ghost Ideal, 훈련 유령 아이디얼) 논문의 "방향 + 생성원 위치 추정" 아이디어로, 루프에 빠지는 오픈 모델을 스캔했습니다. **다른 사람의 정답을 보지 않고도** 가중치와 은닉 상태만으로 루프가 어디에 쓰여 있는지 찾을 수 있는지 확인하는 것이 목적이었습니다.

모든 데이터, 모든 스크립트, 성립한 결과, 성립하지 않은 결과, 그리고 우리가 저지른 실수를 그대로 올립니다.

## 한 줄 결론

Qwen3.5-0.8B라는 모델 하나, 수학 문제 사고 모드에서의 루프라는 문제 하나에 대해서는 스캔 체인이 끝까지 통했습니다.

| 스캔이 답해야 하는 질문 | 결과 |
|---|---|
| 문제가 있는가 | 사후학습 모델은 응답의 53–59%가 루프에 빠짐. 사전학습만 한 Base 모델은 0/16 |
| 언제 시작되는가 | 루프 시작 지점 중앙값 약 5200–6400 토큰 (3072 토큰 안에서는 거의 보이지 않음) |
| 어느 층에 쓰여 있는가 | 마지막 층을 제외하면, 새 문제에서 독립적으로 15층과 19층이 선택됨 |
| 어느 뉴런에 쓰여 있는가 | 층당 64개. 공개된 수정의 128개와 65개가 겹침 (우연 기대값 약 2.3) |
| 방향은 안정적인가 | 서로 겹치지 않는 두 문제 묶음에서 구한 방향의 코사인 0.987 / 0.989 |
| 찾은 것이 원인인가 | 스캔한 방향으로 개입: 엄격한 루프 19/32 → 0/32. 같은 크기의 무작위 방향: 13/32 |
| 문제를 바꿔도 성립하는가 | 세 번째 묶음: 루프 15/32, 이번에도 15층과 19층 선택. 개입 후 8/32 → 0/32, 무작위 방향 10/32 |
| 길이를 충분히 주면 몇 문제를 맞히는가 | 상한 8192 → 16384 → 32768: 3 → 6 → 11 (무수정: 3 → 3, MIT의 수정: 12 → 17 → 24) |

**길이를 충분히 주면**: 8192 토큰 상한에서는 루프가 사라진 뒤에도 정답 수가 늘지 않았습니다(3/32). 상한을 단계적으로 32768(MIT 실험의 평가 상한)까지 올리자 같은 문제에서 정답 수가 3 → 6 → 11이 되었습니다. 무수정 모델은 16384에서도 3입니다. 같은 상한에서 MIT의 수정은 12 → 17 → 24이고, 상한을 올려도 격차는 줄지 않았습니다(9 → 11 → 13). 상한이 정답 수를 제한한 것은 맞지만, 우리와 MIT 사이 격차의 주된 원인은 아닙니다. 실험 I를 보세요.

**하지 못한 것**: 우리 버전은 여전히 MIT의 수정에 못 미칩니다(MIT는 16384에서 이미 17문제 정답). 문제를 찾을 수는 있지만 "무엇으로 고쳐야 맞는가, 얼마나 고쳐야 하는가"의 기준은 빌린 것입니다. [정답이 없다](#정답이-없다)를 참고하세요.

### 실패, 그리고 실패가 찾아 준 경계

| 시도 | 결과 | 원인 | 그 실패로 찾은 경계 |
|---|---|---|---|

| 실험 D: 선택한 뉴런을 0으로 | ⚠️ 위치는 성립, 인과는 불확실 (p=0.13) | 0 처리에는 선택성이 없어 정상 추론도 함께 손상됨 | 위치는 맞음. 개입 방식을 바꿔야 함 |
| 방향 빼기, 용량 1 | ❌ 세 층 모두 유의하지 않음 | MIT의 수정을 용량 1로 봤으나 실제는 6 | 용량이 핵심 (실험 E·F: 루프 19/32 → 0/32) |
| 8192 상한에서 정답 수 비교 | ❌ 3 대 3, 차이가 보이지 않음 | 끝낼 수 있었던 응답을 상한이 잘라냄 | 상한을 32768에 맞출 것 (실험 I: 3 → 6 → 11) |

✅ 통한 부분은 위의 표에 있습니다. 이 표의 실패는 하나하나가 뒤에 성립한 결론으로 이어졌습니다.

## 배경

**TGI 논문.** 2026년 5월, GPT의 "고블린 현상"에서 출발해 논문 네 편을 썼습니다([`papers/`](papers/), 중국어). "훈련이 가중치에 남긴, 한번 촉발되면 출력을 계속 흡수하는 구조"를 환론의 아이디얼에 비유한 것입니다. 논문에는 정의와 측정 공식이 있지만, 그 공식을 실제 모델에서 계산해 본 적은 없었습니다.

**스캔 대상.** 2026년 11월, 한 공개 실험 — MIT CSAIL의 Rikiya Takehi, Jayden Teoh, Alex Zhang, Omar Khattab이 발표한 *Sparks of Weight-Space Programming: LLMs can natively read & write neural network weights*([원문](https://rikiyat.github.io/blog/weight-space-programming), 2026-11-02 공개. 여기서는 "MIT 실험"이라 부릅니다. 저자와 소속은 2026-11-17에 원문과 대조해 확인했습니다) — 에서 LLM 에이전트(Astra)가 Qwen3.5-0.8B의 가중치를 직접 고쳤습니다. 15층과 19층 MLP 출력 행렬에서 각 64개 열만 수정했는데, 수학 문제에서의 루프가 크게 줄었습니다. 로그는 [RikiyaT/lm_understand-logs](https://github.com/RikiyaT/lm_understand-logs)(`exp8_math`)에 공개되어 있습니다.

덕분에 드문 조건이 갖춰졌습니다. **문제가 있다고 알려진 모델과, 그 문제가 어디에 있는지에 대한 다른 사람의 공개 답안**입니다. 그래서 TGI 방법이 이 답안을 보지 않고도 같은 자리를 찾아내는지 검증할 수 있었습니다.

**같은 주의 다른 연구.** Will DePue의 [Checkpoint Forensics](https://unemploymentlabs.com/checkpoint-forensics)(2026-11-12)는 공개된 가중치에서 초기 가중치를 생성한 GPU 종류를 역추적합니다. 훈련이 지우지 못한 초기화 흔적을 읽는 것이라 모델의 행동과는 무관하지만, 가중치에서 읽어낼 수 있는 것이 있다는 또 하나의 사례입니다.

## 실험 설정

- **모델**: `Qwen/Qwen3.5-0.8B`(사후학습 버전, revision `2fc06364715b967f1860aea9cf38778875588b17`, 가중치 해시가 MIT 실험의 기준과 일치)와 `Qwen/Qwen3.5-0.8B-Base`(사전학습만). 24층, 층당 MLP 뉴런 3584개, 잔차 차원 1024.
- **생성**: 사고 모드, temperature 0.6, top_p 0.95, top_k 20, presence penalty 1.5 (MIT 실험의 평가 설정), 상한 8192 토큰.
- **문제**: MIT 실험이 공개한 연습 문제 `math_train.jsonl`. 조건당 32문제, 모든 조건에 같은 난수 시드.
- **루프 판정**: 응답의 끝부분이 엄격하게 주기적으로 반복됨 (마지막 max(4p,160) 토큰 중 90% 이상이 `ids[t]==ids[t-p]`).
- **"뉴런"**: MLP 중간층의 한 차원, 즉 `mlp.down_proj`에 들어가는 값.
- **판정 기준은 모두 실행 전에 적어 두었습니다**(각 절에 표기). 사후 분석은 따로 표시했습니다.
- **하드웨어**: NVIDIA DGX Spark 한 대(통합 메모리). 생성 시 실제로 사용한 GPU 메모리는 최대 약 7.5–11.5 GB. 프로세스가 시스템에서 잡고 있는 양은 설정한 상한까지 늘어납니다(우리는 18–24 GB로 설정).

## 실험 기록 (시간순)

### 첫째 날 (2026-11-15)

**0. 기존 소프트웨어 평가.** 우리 TGI Scanner(GTK 앱, 비공개)의 측정 함수 여섯 개는 실제로는 출력 텍스트 통계였습니다. 논문의 수학적 대상은 하나도 구현되어 있지 않았습니다. 이것이 이틀 작업의 출발점입니다.

**1. 내부 프로브(측정만).** `rcs/tgi_probe.py`

| | Qwen3.5-0.8B-Base | Qwen3.5-4B-Base |
|---|---|---|
| 정확한 엔트로피 μ / σ (bit) | 1.896 / 2.170 | 1.187 / 1.653 |
| μ − 2σ | −2.445 (그 아래로 내려간 스텝 0) | −2.119 (그 아래로 내려간 스텝 0) |
| 엔트로피: 코드 / 수학 / 문학 / 의학 | 1.25 / 0.79 / 3.65 / 1.94 | 0.69 / 0.48 / 2.76 / 1.13 |

발견한 문제: 논문의 엔트로피 감시 임계값 μ−kσ는 음수라서 절대 발동하지 않습니다. 엔트로피는 영역에 따라 크게 다릅니다.

**2. MIT 실험 검증, 1판(실패).** 상한 3072 토큰. "상한 도달 비율"로는 세 조건을 구분할 수 없었습니다(90% / 96% / 94%). 측정 방식이 틀렸습니다. 3072 토큰에서는 정상적인 사고도 상한에 닿고, "8-gram이 앞에 나왔는가"는 문제를 다시 적는 것도 반복으로 셉니다. **이 오류는 코드를 보지 않은 상태에서 지적되었습니다.**

**3. 2판(상한 8192, 루프 = 끝부분의 주기적 반복).** `rcs/tgi_rcs.py`, 데이터 `data/rcs_mit_Qwen3.5-0.8B_v2/`

여기서는 MIT의 층 번호(15, 19)를 썼고, 뉴런 번호는 쓰지 않았습니다.

**4. 첫 번째 블라인드 테스트(불성립).** MIT의 층 번호를 쓰지 않고 "층별 쓰기량 상위 64개의 합"으로 층을 골랐더니 23층과 19층이 선택되었습니다.

| 조건 | 루프 |
|---|---|
| 같은 층 무작위 0 처리 | 19/32 (59%) |

방향이 반대였습니다. 0으로 만들자 루프가 더 많아지고 더 일찍 시작했습니다. 즉 3번의 성립은 MIT가 준 층 번호에 의존한 것이었습니다.

**5. Base 대조.** 같은 설정, 사전학습만 한 Base 모델: 루프 0/16, 답을 낸 것 12/16. 루프는 사후학습 이후에 생긴 것입니다.

### 둘째 날 (2026-11-16)

**A. 마지막 층의 그 뉴런들은 "신뢰도 조절 뉴런"인가? (검증 설계에 변별력이 없었음)** `rcs/tgi_weights.py`

판정 기준: 뉴런의 출력 가중치가 어휘 투영의 근사 영공간에 놓이는 비율. 23층에서 스스로 고른 64개 중 27개가 그 층 상위 5%에 들었고(기대값 3.2), 사전 기준으로는 "성립"입니다. **하지만 15층과 19층의 묶음도 똑같이 몰려 있었습니다(21–31개).** 이 기준으로는 마지막 층을 가려낼 수 없습니다. 사후에 찾은 이유: 유령 방향 자체가 모든 층에서 근사 영공간 쪽으로 기울어 있습니다(비율 0.13–0.44, 무작위 0.05).

**B. Base와 사후학습 모델의 가중치 차이로 루프의 위치를 찾을 수 있는가? (불성립)**

- 사후학습은 언어 모델 가중치 값의 96.6%를 바꿨고, 값 하나당 평균 약 5% 바뀌었습니다.
- MLP 출력 행렬은 층마다 6.8–10.5% 바뀌었고, 두드러진 층은 없습니다.
- 가중치 차이와 유령 방향의 정렬: 모든 층에서 1.05–1.58 (1 = 무작위).
- 가장 많이 바뀐 상위 64개 뉴런과 MIT의 128개는 1개가 겹칩니다.

비교: MIT의 수정은 가중치 131,072개, 언어 모델의 약 0.017%만 건드렸습니다.

**C. 세 층을 따로 시험.** `rcs/tgi_layers.py`, 데이터 `data/rcs_layers_20261116/` (기준 17/32)

| 층 | 64개를 0으로 | 방향을 뺌 (용량 1) |
|---|---|---|
| 15 | 5/32 (16%) | 13/32 (41%) |
| 19 | 20/32 (62%) | 13/32 (41%) |
| 23 | 27/32 (84%) | 16/32 (50%) |

사전 기준으로 성립: 첫 번째 블라인드 테스트의 실패는 마지막 층에서 왔습니다. 0 처리의 이득은 전부 15층에서 나왔습니다.

**D. 두 번째 블라인드 테스트(새 문제, 미리 정한 규칙).** `rcs/tgi_blind2.py`, 데이터 `data/rcs_blind2_20261116/`

규칙: 층 점수 S(l) = d_l · W_l (a_루프 − a_정상), **마지막 층 제외**, 상위 2개 층 선택. 각 층에서 쓰기량이 가장 큰 뉴런 64개. 201–232번 문제로 선택하고 233–264번 문제로 평가. MIT의 층 번호와 뉴런 번호는 쓰지 않음.

- **19층과 15층**이 선택되었습니다(마지막 층의 점수는 2위여서, 제외하지 않았다면 선택되었을 것입니다).
- 선택된 뉴런 중 65개가 MIT의 128개와 겹칩니다.

| 조건 | 루프 | 답을 냄 |
|---|---|---|
| 무수정 | 19/32 (59%) | 3 |
| 스스로 고른 128개를 0으로 | 6/32 (19%) | 4 |

**E. 인과 검증: 짝지은 텍스트 + 로그 확률.** `rcs/tgi_pairs.py`, 데이터 `data/pairs_20261116/`

그 방법을 따라, 손으로 쓴 텍스트 6쌍(같은 문제, 같은 도입부, 하나는 정상적인 검산, 하나는 같은 문장의 반복)으로 수정 뒤 반복 구간과 정상 구간의 평균 로그 확률이 각각 얼마나 변하는지 쟀습니다.

**I. 토큰 상한 점진 시험.** `rcs/tgi_continue.py`, 데이터 `data/continue_20261116/`, `data/continue32k_20261116/`

질문: 8192 상한이 끝낼 수 있었던 응답을 잘라낸 것은 아닌가? MIT 실험의 평가 상한은 32768이고, 수정 뒤 정답 응답의 길이 중앙값이 9171 토큰이라고 보고합니다.

방법: 조건마다 해당 가중치 수정을 적용하고, 8192에서 잘린 응답을 이어서 쓰게 했습니다. 먼저 16384까지, 다음으로 32768까지. 앞부분 토큰은 그대로이고, 이어 쓰는 부분에는 새 난수 시드를 썼습니다.

| 조건 (D의 평가 문제, 32문제) | 정답 @8192 | @16384 | @32768 |
|---|---|---|---|
| 무수정 | 3 | 3 | 실행 안 함 (끝나지 않은 29개 중 28개가 이미 엄격한 루프) |
| 블라인드 방향 + 블라인드 뉴런, 용량 6 | 3 | 6 | **11** |
| MIT의 실제 수정 | 12 | 17 | **24** |

우리 버전의 세부:

| 상한 | 끝까지 씀 | 아직 안 끝남 | 그중 엄격한 루프 |
|---|---|---|---|
| 8192 | 3 | 29 | 0 |
| 16384 | 6 | 26 | 2 |
| 32768 | 13 | 19 | 4 |

- 상한을 두 배로 올릴 때마다 정답 수가 늘었습니다. 16384에서 32768 사이에 새로 끝난 7개 중 5개는 27000 토큰을 넘겨서 끝났습니다.
- 무수정 모델은 길이를 더 줘도 소용이 없습니다. 이어 쓴 뒤 29개 중 28개가 엄격한 루프에 빠졌습니다. "루프는 한번 시작되면 계속된다"는 직접 데이터입니다.
- 32768에서 "끝까지 썼지만 틀린 답" 1건과 "끝났지만 답을 내지 않음" 1건이 나왔습니다.
- 16384에서 아직 끝나지 않은 응답의 마지막 2000 토큰에 나오는 "Wait" 횟수 중앙값: 무수정 52, 우리 44, MIT 14. 우리 수정은 글자 그대로의 반복은 눌렀지만 거듭되는 자기 의심은 누르지 못했습니다.
- 사전 판정: 16384에서 우리가 무수정보다 3개 많음(기준: 7개 이상이면 성립, 3개 미만이면 불성립) → 불확실. 32768에서의 판정(MIT와의 차이가 5 이하면 상한이 격차의 주된 원인, 9 이상이면 아님): 차이는 13(11 대 24) → **상한은 격차의 주된 원인이 아닙니다**.
- MIT와의 격차는 상한을 올릴수록 커졌습니다: 9(@8192) → 11(@16384) → 13(@32768).
- MIT의 수정을 32768까지 돌린 결과(2026-11-17 실행): 27개가 끝났고, 25개가 답을 냈고, 24개가 정답입니다. 끝나지 않은 5개 중 3개는 엄격한 루프입니다. 16384에서 32768 사이에 새로 끝난 10개 중 4개는 27000 토큰을 넘겨서 끝났습니다.

**이 비교를 읽는 법**

- **토큰 상한의 경계를 먼저 찾아야 합니다.** 모델의 출력을 비교 기준으로 쓰는 모든 방법(TGI 포함)은 "응답이 끝나려면 얼마나 길어야 하는가"라는 문턱을 먼저 찾고 나서 비교해야 합니다. 이것은 선택 사항이 아니라 전제 분석입니다. 이 실험에서 8192에서는 3 대 3으로 차이가 보이지 않았고, 32768까지 올려야 조건들이 갈렸습니다.
- **MIT의 수정은 여러 라운드를 거친 결과이고, 우리의 것은 한 라운드입니다.** MIT의 실행(p50c)은 순전파 50회, 158턴, 코드 실행 80회, 20.3시간을 썼습니다. 집계된 50회 중 33회는 같은 문제에서 원래 모델과 수정된 모델을 짝지어 비교한 것으로 매번 정답률이 돌아왔고, 16회는 내부 활성값을 읽은 것입니다(공개된 `passes.md` 참고). 우리의 블라인드 방향과 블라인드 뉴런은 한 번의 스캔과 한 번의 개입에서 나왔고, 정답률 피드백으로 수정을 조정하지 않았습니다(도중에 사람이 추가한 규칙은 "마지막 층 제외" 하나뿐이고, 규모와 용량은 MIT에서 빌렸습니다).
- **여기서 검증한 것은 이론과 메커니즘이 성립하는가이지, 이 시스템이 도달할 수 있는 한계가 아닙니다.** 24 대 11의 격차를 방법의 상한으로 읽어서는 안 됩니다.

이어 쓰기의 정확성: 캐시로 이어 쓴 경우와 전체를 한 번에 순전파한 경우를 비교하면 다음 토큰 logits 차이가 약 0.2입니다(bf16 정밀도 잡음. "배치로 계산"과 "한 건씩 계산"의 차이와 같은 크기). 1순위와 상위 5개는 같습니다.

## 재현

필요한 것: Python 3.10+, PyTorch, Qwen3.5를 지원하는 transformers, safetensors, numpy, GPU (상한 8192에서는 약 8 GB. 32768까지 이어 쓸 때는 프로세스 상한을 18 GB로 설정).

```bash
# 1. 모델
#    Qwen/Qwen3.5-0.8B (revision 2fc06364715b967f1860aea9cf38778875588b17) 와 Qwen/Qwen3.5-0.8B-Base
export TGI_MODEL_DIR=/path/to/Qwen3.5-0.8B
export TGI_BASE_DIR=/path/to/Qwen3.5-0.8B-Base

# 2. MIT 실험의 공개 파일 (이 저장소에서는 재배포하지 않음) 을 Ref/mit_wsp_exp8/ 에 둡니다
#    https://github.com/RikiyaT/lm_understand-logs 의 exp8_math 에서:
#    edit.npz, manifest.json (runs/p50c/edit), math_train.jsonl (practice),
#    p50c_logs/tool_calls.jsonl (runs/p50c 의 로그)

# 3. 몇 분 안에 끝나는 것
cd rcs
python tgi_weights.py     # 실험 A, B. CPU만 사용, 약 10초, 메모리 약 10 GB 필요
python tgi_pairs.py       # 실험 E. 약 1분

# 4. 생성 실험. 조건당 약 19분
python tgi_blind2.py      # 실험 D. 약 95분
python tgi_dose.py        # 실험 F. 약 40분 (D의 출력이 필요)

# 5. 채점과 이어 쓰기
python tgi_grade.py       # 실험 H. CPU만 사용, 약 1분
python tgi_continue.py --extra 8192      # 실험 I. 16384까지, 조건당 약 30–40분
python tgi_continue.py --extra 16384 --conds blind_a6,mit --src ../data/continue_20261116 \
    --out ../data/continue32k_20261116 --batch 13 --max-mem-gb 18      # 32768까지, 배치당 약 75분
```

공개 전에 이 디렉터리의 사본에서 `tgi_weights.py`, `tgi_pairs.py`, `tgi_grade.py`를 다시 실행했고, 숫자는 `data/`와 일치합니다. 나머지 스크립트는 경로만 바꿨고 전체 과정을 다시 돌리지는 않았습니다.

## 이 실험을 어떻게 했는가

연구 질문, 이론, 단계마다의 판단은 본 연구소에서 나왔습니다. 실험의 설계, 코딩, 실행은 AI 모델 Claude Fable 5.2(Anthropic, Claude Code를 통해 사용)와 협업해 우리 장비에서 진행했습니다. 우리 논문과 마찬가지로 협업한 AI 모델의 이름을 표기합니다. 위의 "우리가 저지른 실수" 대부분은 그 협업 과정에서 실제로 일어난 일입니다.
