# TGI-RCS — 在语言模型的权重里扫描"循环幽灵"

> 🇰🇷 [한국어](README.ko.md) | 🇨🇳 中文 | 🇺🇸 [English](README.md)

**이조글로벌인공지능연구소 (LEECHO Global AI Research Lab) & Claude Fable 5.2 · Anthropic** · 2026-11-15 ~ 2026-11-17

两天的实验记录：用 TGI（Training Ghost Ideal，训练幽灵理想）论文里的"方向 + 生成元定位"思路，去扫描一个会陷入循环的开源模型，看能不能在**不借助别人答案**的情况下，从权重和隐状态里找到循环写在哪里。

这里放的是全部数据、全部脚本、成立的结果、不成立的结果，以及我们自己犯的错。

---

## 一句话结论

在 Qwen3.5-0.8B 这一个模型、数学题思考模式下的循环这一种问题上，这条扫描链走通了：

| 扫描要回答的问题 | 结果 |
|---|---|
| 有没有问题 | 后训练版 53%–59% 的回答陷入循环；仅预训练的 Base 版 0/16 |
| 从什么时候开始 | 循环起点中位约 5200–6400 token（3072 token 内几乎看不到） |
| 写在哪一层 | 排除最后一层后，在新题上独立选出第 15、19 层 |
| 写在哪些神经元 | 每层 64 个，与公开改动的 128 个重合 65 个（随机期望约 2.3） |
| 方向稳不稳 | 两批互不重叠的题目算出的方向，余弦 0.987 / 0.989 |
| 扫到的是不是原因 | 沿扫到的方向干预：严格循环 19/32 → 0/32；同样大小的随机方向：13/32 |
| 换一批题还成立吗 | 第三批题：循环 15/32，仍选出第 15、19 层；干预后 8/32 → 0/32，随机方向 10/32 |
| 给够长度后能答对多少 | 上限 8192 → 16384 → 32768：3 → 6 → 11（不改动：3 → 3；MIT 的改动：12 → 17 → 24） |

**给够长度之后**：在 8192 token 的上限下，循环消失后答对的题没有增加（3/32）。把上限逐级放到 32768（MIT 实验的评测上限）后，同一组题的答对数是 3 → 6 → 11；不改动的模型到 16384 仍是 3。同样的上限下 MIT 的改动是 12 → 17 → 24，差距没有随上限缩小（9 → 11 → 13）：上限限制了答对数，但不是我们与 MIT 差距的主要原因。见实验 I。

**没有做到的**：我们的版本仍低于 MIT 的改动（它在 16384 时已答对 17 题）。我们能扫到问题，但"改成什么才算对、改多少"的标准是借来的。详见[没有标准答案](#没有标准答案)。

### 失败，和它们找到的边界

| 尝试 | 结果 | 原因 | 由此找到的边界 |
|---|---|---|---|
| 第一版度量：上限 3072，看"撑满上限的比例" | ❌ 三个条件分不开（90% / 96% / 94%） | 正常思考也撑满上限；复述题目被算成重复 | 上限至少 8192；循环 = 结尾严格周期性重复 |
| 第一次盲测：自选层，最后一层参与排序 | ❌ 循环 59% → 94%，方向相反 | 最后一层和中间层用了同一把尺子 | 选层时排除最后一层（实验 C 证实，实验 D、G 重复） |
| 实验 A：用权重判据解释最后一层 | ❌ 判据没有区分力 | 每一层的方向都偏向同一个子空间 | 判定线必须要求"比对照组更显著" |
| 实验 B：用后训练前后的权重差定位 | ❌ 与公开改动重合 1/128 | 后训练改动了 96.6% 的权重，是弥散的 | 只读权重定位不了，必须先让模型表现出问题 |
| 实验 D：置零选中的神经元 | ⚠️ 定位成立，因果不确定（p=0.13） | 置零没有选择性，正常推理一起受损 | 定位是对的；干预方式要换 |
| 减去方向，剂量 1 | ❌ 三层都不显著 | 把 MIT 的改动当成了剂量 1，实际是 6 | 剂量是关键（实验 E、F：循环 19/32 → 0/32） |
| 在 8192 的上限下比较答对数 | ❌ 3 对 3，看不出差别 | 上限把能答完的回答截掉了 | 上限要对齐 32768（实验 I：3 → 6 → 11） |

✅ 走通的部分见上表；这张表里每一行失败，都对应后面一个成立的结论。

## 背景

**TGI 论文。** 2026 年 5 月，从 GPT 的"哥布林现象"出发，我们写了四篇论文（见 [`papers/`](papers/)），把"训练在权重里留下的、一旦触发就持续吸收输出的结构"类比为环论里的理想。论文给出了定义和度量公式，但这些公式当时从未在真实模型上算过。

**被扫描的对象。** 2026 年 11 月，一组公开实验——MIT CSAIL 的 Rikiya Takehi、Jayden Teoh、Alex Zhang、Omar Khattab 发表的 *Sparks of Weight-Space Programming: LLMs can natively read & write neural network weights*（[原文](https://rikiyat.github.io/blog/weight-space-programming)，2026-11-02 发布；本文称"MIT 实验"；作者与机构已于 2026-11-17 对照原文核实）——让一个 LLM 代理（Astra）直接改写 Qwen3.5-0.8B 的权重：只改第 15、19 层 MLP 输出矩阵的各 64 列，模型在数学题上的循环大幅减少。日志公开在 [RikiyaT/lm_understand-logs](https://github.com/RikiyaT/lm_understand-logs)（`exp8_math`）。

这给了我们一个少见的条件：**一个已知有问题的模型，加上别人公布的"问题在哪里"**。于是可以检验：TGI 的方法不看这份答案，能不能自己找到同一个地方。

**同期的另一项工作。** Will DePue 的 [Checkpoint Forensics](https://unemploymentlabs.com/checkpoint-forensics)（2026-11-12）从公开权重里反推出生成初始权重的 GPU 类型。它读的是训练没有抹掉的初始化痕迹，和模型行为无关，但同样说明权重里有可以读出来的东西。

## 实验设置

- **模型**：`Qwen/Qwen3.5-0.8B`（后训练版，revision `2fc06364715b967f1860aea9cf38778875588b17`，权重哈希与 MIT 实验的基准一致）；`Qwen/Qwen3.5-0.8B-Base`（仅预训练）。24 层，每层 3584 个 MLP 神经元，残差维度 1024。
- **生成**：思考模式，temperature 0.6，top_p 0.95，top_k 20，presence penalty 1.5（MIT 实验的评测设置），上限 8192 token。
- **题目**：MIT 实验公开的练习题 `math_train.jsonl`，每个条件 32 题，同一随机种子。
- **循环判据**：回答的结尾是严格的周期性重复（最后 max(4p,160) 个 token 中 ≥90% 满足 `ids[t]==ids[t-p]`）。
- **"神经元"**：MLP 中间层的一维，即进入 `mlp.down_proj` 的值。
- **判定标准都在运行前写定**（见各节），事后分析单独标明。
- **硬件**：单台 NVIDIA DGX Spark（统一内存）。生成时实际使用的显存峰值约 7.5–11.5 GB；进程向系统占住的量会涨到设定的上限（我们设 18–24 GB）。

## 实验记录（按时间顺序）

### 第一天（2026-11-15）

**0. 现有软件的评估。** 我们自己的 TGI Scanner（GTK 应用，未开源）里的六个度量函数，实际是对输出文本的统计，没有实现论文里的任何数学对象。这是这两天工作的起点。

**1. 内部探针（只测量）。** `rcs/tgi_probe.py`

| | Qwen3.5-0.8B-Base | Qwen3.5-4B-Base |
|---|---|---|
| 精确熵 μ / σ（bit） | 1.896 / 2.170 | 1.187 / 1.653 |
| μ − 2σ | −2.445（0 步低于它） | −2.119（0 步低于它） |
| 熵：代码 / 数学 / 文学 / 医学 | 1.25 / 0.79 / 3.65 / 1.94 | 0.69 / 0.48 / 2.76 / 1.13 |

发现的问题：论文里的熵哨兵阈值 μ−kσ 是负数，永远不会触发；熵随领域差别很大。

**2. 对 MIT 实验做检验，第一版（失败）。** 上限 3072 token。三个条件的"撑满上限比例"分不开（90% / 96% / 94%）。原因是度量错了：3072 token 时正常思考也撑满上限；"8-gram 出现过"把复述题目也算成重复。**这是在没看代码的情况下被指出来的。**

**3. 第二版（上限 8192，循环 = 结尾周期性重复）。** `rcs/tgi_rcs.py`，数据 `data/rcs_mit_Qwen3.5-0.8B_v2/`

使用了 MIT 的层号（15、19），但不使用它的神经元编号：

| 排序方法（两层各取前 64） | 与 MIT 的 128 个重合 | 预写标准 | 结果 |
|---|---|---|---|
| 循环内 − 正常的激活差 | 19 | ≥16 | 成立 |
| 写入幽灵方向的量 | 68 | ≥32 | 成立 |
| 按领域的候选集（数学 Top-1000） | 1 | — | 仅记录 |

| 条件（32 道留出题） | 陷入循环 | 给出答案 |
|---|---|---|
| 不改动 | 17/32（53%） | 5 |
| MIT 的实际改动 | 1/32（3%） | 10 |
| 置零 MIT 的 128 个 | 4/32（12%） | 7 |
| 置零写入量前 64 | 8/32（25%） | 2 |
| 置零激活差前 64 | 11/32（34%） | 3 |
| 置零同层随机 64 | 16/32（50%） | 6 |

**4. 第一次盲测（不成立）。** 不用 MIT 的层号，按"每层写入量前 64 之和"自选层，选到第 23、19 层。

| 条件 | 陷入循环 |
|---|---|
| 同层随机置零 | 19/32（59%） |
| 置零自选的 128 个 | **30/32（94%）** |
| 自选 128 个减去方向（剂量 1） | 13/32（41%） |

方向相反：置零后循环更多、更早。所以上一节的成立依赖了 MIT 给的层号。

**5. Base 对照。** 同样设置，仅预训练的 Base 版：0/16 循环，12/16 给出答案。循环是后训练之后才出现的。

### 第二天（2026-11-16）

**A. 最后一层那批神经元是不是"置信度调节神经元"？（检验设计无效）** `rcs/tgi_weights.py`

判据：输出权重落在词表投影近零空间里的比例。第 23 层自选的 64 个里有 27 个排在本层前 5%（随机期望 3.2），按预写标准"成立"。**但第 15、19 层的组同样富集（21–31 个）**，所以这个判据区分不了最后一层。事后发现原因：每一层的幽灵方向本身就偏向近零空间（比例 0.13–0.44，随机 0.05）。

**B. Base 与后训练版的权重差能不能定位循环？（不成立）**

- 后训练改动了语言模型 96.6% 的权重值，每个平均改动约 5%。
- MLP 输出矩阵每层改动 6.8%–10.5%，没有突出的层。
- 权重差与幽灵方向的对齐：所有层 1.05–1.58（1 = 随机）。
- 改动最大的前 64 个神经元与 MIT 的 128 个重合 1 个。

对照：MIT 只改了 131,072 个权重，约占语言模型的 0.017%。

**C. 三层分别测。** `rcs/tgi_layers.py`，数据 `data/rcs_layers_20261116/`（基准 17/32）

| 层 | 置零 64 个 | 减去方向（剂量 1） |
|---|---|---|
| 15 | 5/32（16%） | 13/32（41%） |
| 19 | 20/32（62%） | 13/32（41%） |
| 23 | 27/32（84%） | 16/32（50%） |

按预写标准成立：第一次盲测的失败来自最后一层。置零带来的好处全部来自第 15 层。

**D. 第二次盲测（新题、写定规则）。** `rcs/tgi_blind2.py`，数据 `data/rcs_blind2_20261116/`

规则：层得分 S(l) = d_l · W_l (a_循环 − a_正常)，**排除最后一层**，取最大的 2 层；每层取写入量最大的 64 个神经元。第 201–232 题选择，第 233–264 题评测。不使用 MIT 的层号和神经元编号。

- 选出**第 19、15 层**（最后一层的得分排第 2，如果不排除会被选中）。
- 神经元与 MIT 的 128 个重合 65 个。

| 条件 | 陷入循环 | 给出答案 |
|---|---|---|
| 不改动 | 19/32（59%） | 3 |
| 置零自选的 128 个 | 6/32（19%） | 4 |
| 同层随机置零 | 11/32（34%） | 8 |
| MIT 的实际改动 | 1/32（3%） | 12 |

定位成立。因果部分按预写标准（比随机对照低 ≥20 个百分点）为**不确定**：差 15.6 个百分点，p=0.13；对不改动 p=0.0009。

**E. 因果验证：成对文本 + 对数概率。** `rcs/tgi_pairs.py`，数据 `data/pairs_20261116/`

读 MIT 实验的原始日志后发现：它最终的公式是 `W = W0 − 6·outer(u, mask·(uᵀW0))`，**剂量是 6**，把写入量从 c 变成 −5c。我们之前一直拿剂量 1 去比。

照它的做法用 6 对手工文本（同题同开头，一条正常验算、一条重复同一句）做检验：改动后，重复段和正常段的平均对数概率各变多少。

| 条件 | 重复段 | 正常段 |
|---|---|---|
| 校准：MIT 的实际改动（它自报 −0.103 / −0.009） | −0.101 | −0.006 |
| 我们的方向 + 我们的神经元，剂量 1 | −0.015 | +0.001 |
| 同上，剂量 2 / 4 | −0.031 / −0.061 | −0.001 / −0.008 |
| 同上，剂量 6 | −0.092 | −0.014 |
| 盲测选出的方向 + 神经元，剂量 6 | −0.082 | −0.015 |
| 我们的神经元 + MIT 的方向，剂量 6 | −0.088 | −0.008 |
| 置零我们的 128 个 | −0.073 | −0.064 |
| 同样大小的随机正交方向 | −0.004 | −0.017 |

- 我们的方向与 MIT 的方向余弦 0.67（第 15 层）/ 0.71（第 19 层）。
- 之前"减方向"效果弱，是剂量问题，不是方向问题。
- 置零没有选择性：重复段和正常段一起降。

**F. 生成确认。** `rcs/tgi_dose.py`，数据 `data/rcs_dose_20261116/`

D 选出的方向和神经元，剂量 6，在 D 的评测题上生成：

| 条件 | 陷入循环 | 给出答案 | 撑满上限 |
|---|---|---|---|
| 不改动 | 19/32（59%） | 3 | 29 |
| **盲测方向 + 盲测神经元，剂量 6** | **0/32** | 3 | 29 |
| 同样神经元 + 同样大小的随机方向 | 13/32（41%） | 2 | 30 |
| MIT 的实际改动 | 1/32（3%） | 12 | 20 |

按预写标准成立（低 41 个百分点，p=0.00003）。**但在 8192 的上限下答案没有增加**：回答不再周期性重复，却仍在一遍遍 "Wait, …" 地重新验算，直到上限。上限放高以后的情况见实验 I。

**G. 第三批题上的重复。** 数据 `data/scan_e2e_20261116/`

把 D 和 F 的流程合成一次运行（选层、选神经元、三个验证条件），用第 265–296 题扫描、第 297–328 题验证。这次运行用的是我们未开源的 TGI Scanner 里的合并版脚本，算法与 `tgi_blind2.py` + `tgi_dose.py` 相同。

- 循环 15/32，起点中位 5872 token。
- 仍选出第 19、15 层；最后一层仍排第 2。

| 条件 | 陷入循环 | 结束 |
|---|---|---|
| 不改动 | 8/32 | 3 |
| 扫描方向，剂量 6 | **0/32** | 6 |
| 同样大小的随机方向 | 10/32 | 4 |

低 31 个百分点，p=0.0004。三批互不重叠的题上结论相同。

**H. 用标准答案判分。** `rcs/tgi_grade.py`，数据 `data/grade_20261116/`

题库自带标准答案。取 `</think>` 之后最后一个 `\boxed` 的内容，归一化后与标准答案完全相同才算对（偏保守，人工核对发现 3 条漏判）。

| 条件（D 的评测题，上限 8192） | 答对 |
|---|---|
| 不改动 | 3/32 |
| 盲测方向 + 盲测神经元，剂量 6 | 3/32 |
| 置零自选的 128 个 | 4/32 |
| 同层随机置零 | 8/32 |
| 同样大小的随机方向 | 2/32 |
| MIT 的实际改动 | 12/32 |

- 后训练版只要答完，几乎都答对。所以在这个模型上，"答对多少"基本等于"在上限内答完多少"。
- Base 版 16 题答对 11 题（人工核对后）；后训练版同样设置下第 1–32 题答对 2 题。

**I. Token 上限渐进测试。** `rcs/tgi_continue.py`，数据 `data/continue_20261116/`、`data/continue32k_20261116/`

问题：8192 的上限是不是把本来能答完的回答截掉了？MIT 实验的评测上限是 32768，它报告改动后答对的回答中位长度是 9171 token。

做法：对每个条件装上对应的权重改动，从 8192 处被截断的回答接着往下写，先到 16384，再到 32768。前面的 token 不变；续写用新的随机种子。

| 条件（D 的评测题，32 题） | 答对 @8192 | @16384 | @32768 |
|---|---|---|---|
| 不改动 | 3 | 3 | 未跑（29 条未结束的回答里 28 条已陷入严格循环） |
| 盲测方向 + 盲测神经元，剂量 6 | 3 | 6 | **11** |
| MIT 的实际改动 | 12 | 17 | **24** |

我们的版本的细节：

| 上限 | 结束 | 仍未结束 | 其中严格循环 |
|---|---|---|---|
| 8192 | 3 | 29 | 0 |
| 16384 | 6 | 26 | 2 |
| 32768 | 13 | 19 | 4 |

- 上限每翻一倍，答对数都在涨。从 16384 到 32768 新结束的 7 条里，5 条是在 27000 token 之后才结束的。
- 不改动的模型给再多长度也没用：续写后 29 条里 28 条陷入严格循环。这是"循环一旦开始就持续"的直接数据。
- 到 32768 时出现了 1 条"答完但答错"和 1 条"结束但没给出答案"。
- 16384 处仍未结束的回答，最后 2000 token 里 "Wait" 出现次数的中位数：不改动 52，我们的 44，MIT 的 14。我们的改动压住了逐字重复，没有压住反复的自我怀疑。
- 预写判定：到 16384 时我们比不改动多 3 条（标准：多 7 条以上成立，不到 3 条不成立）→ 不确定。到 32768 的判定（与 MIT 的差距 ≤5 则上限是差距的主因，≥9 则不是）：差距是 13（11 对 24）→ **上限不是差距的主要原因**。
- 与 MIT 的差距随上限放宽而变大：9（@8192）→ 11（@16384）→ 13（@32768）。
- MIT 的改动到 32768（2026-11-17 补跑）：结束 27 条、给出答案 25 条、答对 24 条；未结束的 5 条里 3 条是严格循环。从 16384 到 32768 新结束的 10 条里，4 条在 27000 token 之后才结束。

**怎么读这个对比**

- **Token 上限的边界要先摸清。** 凡是拿模型的输出当比较标准的方法（包括 TGI），都要先找到"回答需要多长才能写完"这个阀门，再做比较。这是前提分析，不是可选项。本实验里 8192 下是 3 对 3，看不出差别；放到 32768 才分得开。
- **MIT 的改动是多轮迭代的结果，我们的是单轮。** MIT 的那次运行（p50c）用了 50 次前向轮次、158 个回合、80 次代码运行、20.3 小时；计入的 50 次里有 33 次是原模型与改动后模型在同一批题上的成对比较，每次都返回答对率，另有 16 次读取内部激活（见它公开的 `passes.md`）。我们的盲测方向和盲测神经元是一次扫描、一次干预，没有用答对率反馈去调整改动（中间只有一次人工加的规则：排除最后一层；规模和剂量借自 MIT）。
- **这里验证的是理论和机制是否成立，不是这套系统能做到的极限。** 24 对 11 的差距不能读成方法的上限。

续写的正确性：缓存续写与整段前向相比，下一个 token 的 logits 相差约 0.2（bf16 精度噪声，与"批量算"对"单条算"的差相同），首选和前 5 名一致。

---

## 没有做到的和局限

- **只有一个模型、一种问题。** Qwen3.5-0.8B，数学题思考模式下的循环。
- **样本小。** 每个条件 32 题。
- **"排除最后一层"是失败后人工加的规则**，不是方法自己推出来的。最后一层那批神经元是什么功能，没有回答。
- **规模和剂量是借来的。** "2 层 × 64 个"和剂量 6 都来自 MIT 实验。
- **必须先让模型跑出循环才能扫。** 只读权重扫不出来（实验 B）。
- **循环判据只衡量"严格周期循环"**，不衡量是否完成。
- **判分器偏保守**，写法不同的正确答案会被判错（人工核对发现 3 条）。
- **32768 的结果是两次续写拼接出来的**：续写用了新的随机种子，不是同一次运行；MIT 原实验的 32768 是一次生成。
- **第一天和实验 C、D、F 的生成都只到 8192**，那些表里的"给出答案"数被上限截断了。
- **论文的六项度量，除循环起点外都没有实现。** 环论的形式化没有被这些实验验证。
- 随机对照都只有一组。

---

## 我们犯过的错

写在这里，是因为它们和结果一样是这两天的事实。

1. 第一版度量失效：上限太短、"8-gram 重复"把复述也算进去。
2. 第一次盲测把最后一层和中间层放在同一把尺子上排序。相关文献（最后一层有调节置信度的神经元）是已知的，设计时没有用上。
3. 实验 A 的判定线没有要求"比对照层更富集"，字面成立但没有区分力。
4. 把 MIT 的改动当成"减去方向"（剂量 1）去比，实际是剂量 6。它的公式就写在最终报告里。
5. 一度把目标带偏：TGI 是扫描问题的系统，我们却开始拿"修复后答对多少题"当标准。
6. 把一个临时的想法（按领域划分候选集）当成理论预测去检验。
7. 一次运行因为计算全词表 logits 撞上内存上限，丢了 28 分钟的结果。
8. 与 MIT 的结果比较时，token 上限没有一开始就对齐它的 32768。为了省时间用了 8192，结果"答对数"的比较不成立。
9. 内存报错了口径：一直报"峰值约 7.5 GB"（实际使用量），而进程向系统占住的是约 23 GB。在统一内存的机器上，这个差别很要紧。

---

## 没有标准答案

现在的模型仍然是黑盒。这三项工作都是先在模型外面找一个确定的东西当锚，再反推权重：

| | 外部的锚 | 摸到的 | 摸不到的 |
|---|---|---|---|
| Checkpoint Forensics | 随机数生成器的确定性 | 初始权重在哪类芯片上生成 | 训练学到了什么 |
| MIT 实验 | 数学题的标准答案 | 改哪些神经元能多答对题 | 这些权重为什么错 |
| 本仓库 | 循环态与正常态的行为对比 | 循环写在哪层、哪些神经元、什么方向 | 改成什么算对、改多少 |

没有一家能正向地"读权重就知道会发生什么"。要从扫描再走到修正，需要一个判别权重对错的对照标准，这是我们现在没有的。

我们是盲人摸象，但摸到了一些真实的东西。数据全部公开，欢迎继续摸。

## 复现

需要：Python 3.10+、PyTorch、支持 Qwen3.5 的 transformers、safetensors、numpy，一块 GPU（上限 8192 时约需 8 GB；续写到 32768 时我们把进程上限设在 18 GB）。

```bash
# 1. 模型
#    Qwen/Qwen3.5-0.8B（revision 2fc06364715b967f1860aea9cf38778875588b17）和 Qwen/Qwen3.5-0.8B-Base
export TGI_MODEL_DIR=/path/to/Qwen3.5-0.8B
export TGI_BASE_DIR=/path/to/Qwen3.5-0.8B-Base

# 2. MIT 实验的公开文件（本仓库不再分发），放到 Ref/mit_wsp_exp8/
#    来自 https://github.com/RikiyaT/lm_understand-logs 的 exp8_math：
#    edit.npz、manifest.json（runs/p50c/edit）、math_train.jsonl（practice）、
#    p50c_logs/tool_calls.jsonl（runs/p50c 的日志）

# 3. 几分钟内能跑完的
cd rcs
python tgi_weights.py     # 实验 A、B，仅 CPU，约 10 秒，需约 10 GB 内存
python tgi_pairs.py       # 实验 E，约 1 分钟

# 4. 生成类实验，每个条件约 19 分钟
python tgi_blind2.py      # 实验 D，约 95 分钟
python tgi_dose.py        # 实验 F，约 40 分钟（依赖 D 的输出）

# 5. 判分和续写
python tgi_grade.py       # 实验 H，仅 CPU，约 1 分钟
python tgi_continue.py --extra 8192      # 实验 I，到 16384，每个条件约 30–40 分钟
python tgi_continue.py --extra 16384 --conds blind_a6,mit --src ../data/continue_20261116 \
    --out ../data/continue32k_20261116 --batch 13 --max-mem-gb 18      # 到 32768，每批约 75 分钟
```

发布前我们在本目录的副本上重跑了 `tgi_weights.py`、`tgi_pairs.py` 和 `tgi_grade.py`，数字与 `data/` 一致。其余脚本只改了路径，未重新跑完整流程。
